## Diary Entry: Fixing My Python & Jupyter Environment

**Context**
I was working on a shared machine (same Linux user for everyone) and VS Code couldn’t run notebook cells because `ipykernel` was missing. Installing anything blindly could affect others, so I had to be careful and do this the *right* way.

**What went wrong initially**
VS Code showed a workspace environment called `scdiff-env`, but it turned out not to be a real Python environment. It had activation scripts but no `python` or `pip`. Activating it changed the prompt but didn’t actually switch Python, which caused confusion and blocked safe installation of `ipykernel`.

**The clean solution**
To avoid touching system Python or the shared conda base, I created a brand‑new, isolated conda environment named `scDiffRNA2ndFeb2026` with Python 3.10. This gave me a private Python setup for my project while respecting the shared server.

**Why activation mattered**
I made sure only *one* environment was active at a time (no stacking). I verified the active Python by checking the executable path. Once it pointed to `anaconda3/envs/scDiffRNA2ndFeb2026/bin/python`, I knew everything I did next would affect only my environment.

**Installing ipykernel**
I installed `ipykernel` inside the new conda environment. This step is essential because `ipykernel` is the engine that allows Jupyter/VS Code to execute notebook cells. Without it, notebooks can’t run even if Python exists.

**What “registering the kernel” means**
Registering the kernel does *not* install Python or libraries. It simply tells Jupyter where a usable Python lives. This creates a small metadata entry so that VS Code/Jupyter can list the environment by name and start it when I select it.

**Result**
After registering, my environment appeared as **Python (scDiffRNA2ndFeb2026)** in the kernel picker. Selecting it ensures all notebook cells run with the correct Python and libraries.

**Why this approach is correct**
I avoided modifying system Python and conda base, respected the shared machine, and ended up with a clean, reproducible setup. This is proper research and lab‑server hygiene.

**Final takeaway**
I created an isolated Python environment, enabled it to run notebooks, and explicitly told Jupyter how to find it. From now on, selecting **Python (scDiffRNA2ndFeb2026)** guarantees my notebooks run safely and correctly.
